## 0. 먼저 — 앞으로 지킬 규칙 (가장 중요)

1. **칸 이름·허용값을 바꾸기 전에 ERP 에 먼저 알린다.** 9/9 요금_신뢰도 어휘가 통보 없이 바뀌어 992곳이 잘못 처리됐다. 바꿀 땐 `옛 이름/값 → 새 이름/값` 표를 `_ERP인계/칸값_사양_YYYYMMDD.md` 로 먼저 준다.
2. **이름·위치 칸은 바꾸지 않는다.** ERP 열쇠가 `이름|위치` 라 하나라도 바뀌면 다른 공간으로 들어와 중복이 생긴다(9/9 → 9/17 사이 82곳). 바꿔야 하면 `옛 이름|옛 위치 → 새 이름|새 위치` 표를 같이 준다.
3. **ERP 에서 사람이 고친 값은 원본보다 우선한다.** ERP 가 `_ERP인계/사람수정_YYYYMMDD.csv`(이름·위치·칸·옛값·새값) 를 넘기면 다음 파일에 반드시 반영한다. 사장님이 ERP/시트에서 새로 추가한 공간도 같은 방식으로 넘긴다.
4. 삭제는 행을 지우지 말고 `행사적합=부적합/폐업의심` + `제외사유` 로 표시한다. ERP 가 판정을 읽어 추천에서 뺀다.

## 1. 열 정리 — ERP 가 스스로 처리함 (DB팀 작업 없음)

157열 중 47열은 빈 열·값이 같은 열·옛 스크랩 열·작업 이력 열이라 **ERP 가 적재하면서 정리한다**
(`src/lib/venueColumns.mjs`). 원본 파일은 지금 형태 그대로 줘도 된다. 드라이브 스냅샷에 원본이 남으니 잃는 것은 없다.

- 버림: 플랫폼 · 쉐어잇중복 · 통화내용 · 접근제한_표준(빈 열), 수용_min/max(수용_적용과 100% 같음)
- 합침: 주말이용_표준→주말이용 · 구_대관방법→대관방법 · 구_전화→전화_원본 · 근거출처→출처URL · 공간명→대표공간명
- 옛 스크랩 5열(좌석/수용/면적 · 공간 웹사이트 링크 · 대관비 · 대관가능 날짜 · 비고) → `원문_메모` 한 칸
- 작업 이력 17열(탐색시도 · 검증_* · 구_요금 · 시트_* · 조건_확인일 · 영리_검증일 · 접속상태 · 최초수집일 · 유형_원본 · 전화_원본 · 주말_원문) → ERP 내부 보관, 시트에는 안 나감

DB팀 쪽에서 원하면 같은 규칙으로 원본도 줄여도 되지만, **줄일 땐 0절 1번대로 사양서를 먼저** 줄 것.

확인만 부탁:
- `우천시` ≈ `그늘천막` 65행 중 63 동일 → 복사 실수인지.
