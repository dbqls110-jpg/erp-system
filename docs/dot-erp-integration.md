# DOT 업무비서 연결

## 실제 활성화 조건

코드 구현만으로 DOT 일정이 저장되거나 운영 계정이 생성되지는 않는다.
다음 순서의 각 결과를 확인해야 완료이다.

1. 검증한 커밋을 운영 main에 push하고 Render 배포가 live인지 확인한다.
2. Render 빌드의 migrate deploy로 dot_reports 테이블과 DOT 계정이 생성되었는지 확인한다.
3. 운영 Render에 DOT_INTEGRATION_SECRET을 전용 난수(32바이트 이상, hex 권장)로 등록한다.
   기존 ERP_AGENT_API_KEY, 브리지 키 또는 VenueDA 키를 재사용하지 않는다.
   기존 쓰기용 키와 같은 값으로 설정되면 DOT 인증은 닫힌 상태로 유지된다.
4. DOT의 private sign-in 폼/클라우드 브라우저에만 같은 인증키를 입력한다.
   인증키를 채팅·문서·명령행 인수·스크린샷·로그·URL에 기록하지 않는다.
5. DOT 클라우드에서 조회·audit 보고 송신·ERP 수신·재송신 중복 방지를 실제로 검증한다.
6. DOT의 Scheduled에 매일 10:00 Asia/Seoul 일정을 저장하고 활성 상태를 확인한다.
   Codex의 로컬 자동화나 회사 PC 작업 스케줄러로 대신 등록하지 않는다.

## 권한

- 시스템 계정: erp-dot-assistant / DOT 업무비서 / role=dot, isAgent=true.
- 내부 식별 주소 dot@agents.erp.invalid는 실제 이메일/Google 계정이 아니다.
- 화면 로그인: /dot-login (NextAuth Credentials, 전용 인증키).
- 로그인 후 /dot-report에서 같은 HTTP-only 세션으로 자료 조회·보고 전송을 한다.
  DOT이 키를 채팅에 받거나 Bearer 값으로 추출할 필요가 없다.
  브라우저 보고는 NEXTAUTH_URL과 일치하는 Origin/same-origin 요청만 허용한다.
- 조회 메뉴: 대시보드, 프로젝트, 일정, 메신저, 공간, 문의, 거래처, 파트너, 재무, 시트.
- ID/비밀번호 저장소, 관리자, 근태·휴가 개인정보 메뉴는 허용하지 않는다.
- 관리자 메뉴 설정에 수정 권한을 잘못 켜도 DOT의 edit 권한은 항상 false.
- Server Action 및 일반 POST/PUT/PATCH/DELETE는 DOT 세션에서 차단.
- 보고는 아래 전용 API에서만 작성 가능하며 수신자는 서버 고정 dbqls110@gmail.com.
- 일반 공용 API 키와 다르므로 기존 /api/agent/* 수정 API에는 인증되지 않는다.
- 계정 비활성화/role 변경/키 교체 시 API와 화면 세션은 다시 검증하여 차단한다.

## API

HTTPS, Authorization: Bearer [private DOT credential].

서버 간 호출의 Bearer 계약은 유지한다. DOT 브라우저는 전용 로그인 세션으로도
아래 두 API만 사용할 수 있다. 다른 계정의 세션·일반 API 쓰기는 허용하지 않는다.
화면 전송은 /dot-report에서 실행 ID·내용을 입력하고 전송하며, 같은 보고 재전송으로
중복 없는 응답을 확인할 수 있다. 실제 최초 수신·메신저 표시는 별도로 확인한다.

GET /api/agent/dot/context?page=1

프로젝트와 체크리스트·견적서 파일명·금액 건, VenueDA 미전달 답변 개수,
브리지 상태를 읽는다. page당 100건. hasMore=true면 다음 페이지도 읽어야 한다.
다른 상담 원문·인증정보·직원 개인정보는 이 응답에 포함하지 않는다.
GET은 시트 생성이나 동기화 작업을 실행하지 않는다.
서버 프로세스당 분당 30회 조회 제한. 여러 인스턴스 운영 전 공유 제한 저장소로 전환 필요.

POST /api/agent/dot/reports

```json
{"runId":"daily-2026-10-15","kind":"daily","body":"확인한 사실과 프로젝트 링크, 누락 항목, 필요한 결정"}
```

kind는 daily 또는 audit. 수신자/발신자 지정은 거부한다.
daily는 한국시간 오전 10시 이후 하루 한 번만 저장한다. 같은 내용의 재전송은 200,
최초 생성은 201. 이미 보낸 보고의 내용을 바꾸는 요청은 409.
runId를 재시도마다 바꾸지 않는다. audit 포함 하루 총 8회 제한.
DB 잠금과 단일 트랜잭션으로 보고 기록·메시지·대화 갱신을 함께 저장한다.
메시지가 ERP 목록에 보이고 안읽음 배지가 생기는지 확인한다.

## DOT에 전달할 업무 지시

자체 클라우드 컴퓨터와 브라우저만 사용한다. 회사 PC/로컬 위임을 만들지 않는다.
ERP 운영 사이트 https://erp-system-lojo.onrender.com 을 위 전용 권한으로 사용한다.
다른 진행 중 업무와 일정을 중단하거나 덮어쓰지 않는다.

매일 10:00 Asia/Seoul에 모든 페이지의 프로젝트 자료를 읽고 마감 임박·기한 초과,
담당자/일정/업무 누락, 견적서와 매출·매입 불일치, 미전달 답변/브리지 이상을 점검한다.
관측한 사실, 추정, 미검증을 구분하고 ERP 계정 dbqls110@gmail.com에 보고한다.
문제가 없으면 실제 확인한 범위를 적고 "오늘 점검 이상 없음"을 보낸다.
수신 실패를 성공으로 보고하지 말고 같은 runId/내용으로 재시도한다.
삭제·편집·등록·결재·고객 발송·시트 변경·파일 업로드·배포는 하지 않는다.

최초 ERP 화면 검증: 허용 메뉴 이동, 검색·필터, 프로젝트/공간 상세, 지도,
견적서 파일명과 금액 표시, 보고 수신 경로를 읽기 전용으로 확인한다.
권한 밖 메뉴는 의도적으로 차단되는 것이며 오류로 판정하지 않는다.
쓰기 동작과 견적서 삭제·재업로드 재현은 운영 원본으로 실행하지 않는다.
필요하면 정확한 차단/재현 조건을 보고하고 별도 격리 환경을 요청한다.

일정 활성화와 연결 완료를 추정하지 말고 실제 저장된 시간대·시각·대상·첫 송수신 결과를 회신한다.

## 보고 누락 감시와 업로드 복구

회사 PC가 아닌 `.github/workflows/erp-maintenance.yml`이 한국시간 09:00~18:45,
15분 간격으로 전용 POST /api/agent/maintenance를 호출한다. GitHub 예약 실행은 지연될 수 있어 정확한 시각을 보장하지 않는다.
누락 알림은 10:15 이후 당일 daily 보고가 없을 때 소유자 메신저에 하루 한 번만 보낸다.
DOT 자체가 오프라인이어도 감시 키는 독립적이다. 미설정 상태에서 감시가 켜졌다고 보고하지 않는다.

배포·첫 보고 검증 후 사용자가 비공개 설정 화면에서 다음을 설정한다:

1. Render의 ERP_MAINTENANCE_SECRET과 GitHub 저장소 Actions Secret의 ERP_MAINTENANCE_SECRET에 같은 전용 난수 키를 설정한다(32자 이상, 다른 키와 재사용 금지).
2. Render DOT_MONITOR_START_DATE를 실제 보고를 시작할 한국 날짜(YYYY-MM-DD)로, DOT_MONITOR_ENABLED를 true로 설정한다.
3. GitHub Actions Variable의 ERP_MAINTENANCE_ENABLED를 true로 설정한다. 코드만 배포하면 작업은 실행되지 않는다.
4. Actions 수동 실행에서 200과 복구 결과를 확인한다. 로그에는 응답 본문·인증정보가 출력되지 않는다.

업로드 복구는 파일 전송 전에 DB에 작업을 기록하고 Drive 파일의 비공개 appProperties에 복구 ID를 붙인다.
DB 저장 실패/응답 유실 시 복구 ID·파일명·크기·SHA-256이 일치하는 파일을 찾아 파일·금액·완료 상태를 함께 저장한다. 재업로드·Drive 파일 삭제는 하지 않는다.
한 번에 최대 5건, 작업당 최대 8회 재시도하며 이후 needs_attention으로 남겨 사람이 확인한다.
작업 등록 전 DB가 실패한 경우에는 Drive 전송을 시작하지 않는다.
배포 전 만들어진 과거 미연결 파일은 복구 ID가 없어 자동 처리하지 않는다.
프로젝트의 ‘업로드 복구’ 버튼은 현재 프로젝트의 대기 작업만 확인한다.

견적서 ‘금액 재분석’은 내부용 파일의 최신 버전만 지원한다. 미리보기 후 확인하면 원본을 재판독하며,
파일 또는 ERP 금액이 그 사이 변경되면 중단한다. 판독 불가 파일은 기존 금액을 유지한다.
