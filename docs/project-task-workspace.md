# 오늘 챙길 일 · 프로젝트 · ERP 캘린더

2026-11-17: 구현 및 격리 검증 완료. 운영 배포와 신규 migration은 사용자 승인 대기. main push는 Render 자동 배포를 일으키므로 실행하지 않았다.

2026-11-18 배포 범위: 프로젝트 목록의 새 작업 화면(`ProjectWorkspace`)은 아직 개편 중이므로 이번 연락 상태·문의함 배포에서 제외한다. 기존 프로젝트 목록은 유지한다. 아래 상단 오늘 목록·목록 정렬 설명은 로컬 구현에 관한 것이며, 이번 운영 반영 범위는 상세 업무·전체 완료·캘린더 연결 및 해당 데이터 모델이다.

## 화면과 한 원본

- 프로젝트 페이지 상단은 오늘 확인할 업무(지난 확인일 포함), 아래는 기존 프로젝트 카드다. 별도 업무 페이지나 이중 입력 폼을 만들지 않았다.
- 기존 `ChecklistItem` 한 행에 담당자, 업무 상태, 다음 확인일, 업무 마감일, 대기 상대, 수정 버전을 추가한다. 기존 ID·내용·완료 기록을 보존한다.
- 상단, 상세 체크리스트와 캘린더는 같은 업무 ID를 참조한다. 캘린더는 조회 시 투영하므로 별도 CalendarEvent 복제나 Notion 쓰기는 없다.
- 날짜를 비우면 오늘 목록과 캘린더에 임의로 넣지 않는다. 프로젝트에서는 날짜 미정·담당자 없음·다음 할 일 미등록을 확인할 수 있다.
- 확인일과 마감일이 같은 날이면 한 일정만 표시하고, 다른 날이면 각각 표시한다. 캘린더에서 원래 프로젝트 업무로 이동한다.
- 내 업무/전체 직원 선택과 회사·연도·월 필터는 분리한다. 하단 필터로 다른 프로젝트를 보더라도 오늘 할 일은 빠지지 않는다.
- 프로젝트 정렬: 최근 등록순(서버 순서 유지), 마감 가까운 순(미정/유효하지 않은 날짜는 뒤), 이름순. 카드에서도 프로젝트 마감일을 표시한다.

## 두 가지 완료 처리

- 업무 체크는 그 업무의 완료 시각과 프로젝트 진행률만 갱신한다. 프로젝트 상태나 지급 완료를 바꾸지 않는다.
- 목록·상세의 `프로젝트 완료`는 확인창 뒤 상태를 completed, 진행률을 100으로 저장한다. 체크리스트가 없어도 가능하다.
- 전체 완료는 개별 업무의 체크·파일·견적서·금액·지급 기록을 변경하지 않는다고 확인창에 알린다.
- `완료 취소`는 active로 복구하고 기존 업무 완료 비율로 진행률을 재계산한다. 업무가 없으면 0%다.

## 권한과 저장

- 쓰기는 기존 `requireEditAccess("projects")`를 통과해야 하며 외부·비활성 계정은 거부한다. 외부 프로젝트 화면은 기존 최소 정보 DTO를 유지하고 내부 업무·직원 후보를 조회하지 않는다.
- 캘린더 업무 조회도 프로젝트 열람 권한이 필요하다. 외부 계정에는 업무 일정과 전체 프로젝트 선택 후보를 반환하지 않는다.
- 프로젝트 행 잠금으로 순서 배정과 진행률 계산을 직렬화한다. 업무 수정/삭제/체크는 버전 비교를 사용한다.
- 생성 request ID를 재사용하면 중복 행을 만들지 않는다. 프로젝트 전체 완료도 기대 상태와 잠금으로 오래된 화면의 다른 상태를 덮지 않게 한다.
- 보이는 탭에서만 60초 갱신하며 편집 중에는 업무 목록 갱신을 멈춘다.

## 검증과 배포

- 신규 `20261117090000_project_task_workspace`는 열·FK·체크·인덱스 추가와 checklist_items RLS 활성화만 수행한다. 행 삭제·금액 변경·기존 완료 기록 재작성은 없다.
- 격리 PostgreSQL(loopback 55433, erp_cost_test)에 migration 적용 후 실제 DB 테스트 21개(업무 9, 지급 12) 통과. 운영 DB에 적용하지 않았다.
- 기존 스키마/업무 완료 기록 보존, 같은 요청 8회 재시도, 서로 다른 업무 8개 동시 등록, 같은 버전 동시 수정 충돌, 전체 완료 8회 재시도, 체크리스트 없는 프로젝트 완료/취소, 금액·파일·업무 체크 보존을 검증했다.
- 전체 기본 테스트: 824 통과, 37 선택적 통합 테스트 건너뜀. 타입 검사·린트·webpack build 통과.
- 실제 컴포넌트와 격리 DB를 연결한 브라우저에서 저장→오늘 목록→날짜 이동→캘린더→상세→체크/취소, 프로젝트 완료/취소, 정렬, 모바일 메뉴 Esc/초점 복귀, 389px 가로 넘침 없음을 확인했다. 메일 화면은 가상 자료다.
- 로컬 `.next`가 다른 드라이브 junction이라 빌드 시 C:의 임시 출력 경로를 사용했다. 임시 next.config/tsconfig 변경은 복원했으며 운영 설정 변경은 없다. build와 tsc를 동시에 실행하면 생성 타입 정리 중 파일 누락이 발생하므로 최종 타입 검사는 build 종료 후 단독 실행했다.
- 디자인 검사 경고 2개는 기존 ERP 보라색 계열 유지에 대한 일반 탐지다. 신규 팔레트/그라데이션을 도입하지 않았다.
- 캡처: workspace `outputs/project-task-validation-20261117/`. 가상 프로젝트/문의 캡처는 운영 저장 성공의 증거가 아니며 네이버 운영 수신 증거와 구분한다.

배포 승인 후 기존 스키마/백업·migration 상태 확인 → 안전한 변경만 동기화 → Render migration/build → 운영에서 내부/외부 권한, 완료·취소, 날짜 이동·캘린더 연결 확인 순서로 진행한다.
