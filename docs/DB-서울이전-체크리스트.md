## 1. Render 에서 주소 바꾸기 (5분)

1. https://dashboard.render.com 접속 → 로그인
2. 왼쪽 목록에서 **erp-system** 서비스 클릭
3. 왼쪽 메뉴 **Environment** 클릭
4. `DATABASE_URL` 항목을 찾아 **Edit**(연필 아이콘) 클릭
5. **기존 값을 지우고**, 아래 값을 붙여넣는다

   값은 `C:\dev\erp 시스템\erp-system\.env` 파일의
   **`SEOUL_DATABASE_URL=` 뒤에 있는 주소 전체**다.

   ```
   postgresql://postgres.bdqcylvydocsiecuzmvx:비밀번호@aws-0-ap-northeast-2.pooler.supabase.com:5432/postgres
   ```

   확인: `ap-northeast-2` 와 `pooler` 가 들어 있어야 한다.
   `us-east-1` 이 보이면 옛 주소다.

6. **Save Changes** → 자동으로 다시 배포된다 (2~4분)

### 바꾸지 말 것
`DATABASE_URL` **하나만** 바꾼다. 다른 항목(구글·카카오·노션 키 등)은 손대지 않는다.
`SEOUL_DATABASE_URL` 은 Render 에 넣을 필요 없다 — 로컬 작업용이다.

## 2. 바꾼 뒤 확인 (5분)

배포가 끝나면 순서대로 본다.

- [ ] 로그인이 되는가
- [ ] **공간 DB** 에서 검색 → **3,721곳** 나오는가
- [ ] **ID 관리** 에 **21개** 있는가
- [ ] **사이드바를 눌러 이동할 때 눈에 띄게 빨라졌는가** ← 이게 이번 작업의 목적
- [ ] 메신저에서 AI 비서에게 아무거나 물어봐서 답이 오는가
- [ ] 캘린더에 일정이 보이는가

---

## 3. 이상하면 되돌리기 (2분)

Render → Environment → `DATABASE_URL` 을 **원래 미국 주소로 되돌리고** Save.

미국 DB 를 지우지 않았으므로 그동안의 자료도 그대로 있다.
옛 주소는 로컬 `.env` 백업이나 Render 의 변경 이력에서 찾을 수 있다.

---

## 알아 둘 것

**회사 PC 의 AI 브리지는 건드릴 필요 없다.**
브리지는 DB 에 직접 붙지 않고 ERP 서버에 HTTP 로만 이야기한다.
(`bridge/bridge.ps1` 에 DB 관련 설정이 하나도 없는 것을 확인했다.)

**주소를 바꾸는 순간부터 새 자료는 서울에만 쌓인다.**
그 뒤에 미국으로 되돌리면, 서울에서 만든 자료는 따라오지 않는다.
되돌릴 거면 되도록 빨리 판단하는 편이 낫다.

**미국 DB 는 최소 일주일은 지우지 말 것.** 되돌릴 유일한 길이다.
일주일 뒤 문제가 없으면 그때 정리한다.
