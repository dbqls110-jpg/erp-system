# 매출 날짜 집계 데이터 변경 (2026-10-29)

범위: `ProjectAmount`(프로젝트 매출 건), `CompanyFinanceEntry`(직접 회사 장부). 기존 관계는 유지한다.

`Project 1 ── * ProjectAmount` / `User 1 ── * CompanyFinanceEntry`.

| 필드 / 용어 | 형식 | 의미 |
| --- | --- | --- |
| paidDate / 실제 입금일 | nullable YYYY-MM-DD | 최우선 집계일 |
| invoiceDate / 계산서 발행일 | nullable YYYY-MM-DD | 실제 입금일 미정일 때 사용 |
| expectedPaymentDate / 입금 예정일 | nullable YYYY-MM-DD | 입금일·발행일이 미정일 때 임시 집계 |
| createdAt / 등록일 | 기존 DateTime 유지 | 감사용. 프로젝트 매출 월을 결정하지 않음 |
| CompanyFinanceEntry.date / 기존 발생일 | 기존 String 유지 | 과거 직접 입력 날짜 보존. 새 매출은 빈 문자열, 매입·카드는 기존 용도 유지 |

규칙:

- 매출 한 건을 단 하나의 기준일에만 집계한다. 실제 입금일 → 발행일 → 예정일 우선순위.
- 과거 직접 장부의 발생일은 새 날짜가 없는 동안에만 사용하며 화면에 ‘기존 발생일’로 표시한다.
- 프로젝트 매출에 날짜가 없으면 ‘날짜 미정’ 별도 목록에 표시하고 월·분기·연간 합계에서 제외한다. 미정 목록은 회사 필터만 적용한다.
- 세 날짜 수정 시 이전 월에서 빠지고 새 월에 들어간다. 금액·작성일·원본 견적서는 변경하지 않는다.
- 날짜만 수정하는 API에서 직접 장부의 기존 발생일 fallback을 빈 값으로 해제한다. 모든 날짜를 비우면 미정이다.
- 날짜는 1900~2200년 실제 달력 날짜만 허용하며, 날짜 문자열을 UTC로 이동시키지 않는다.
- migration은 nullable 열 6개 추가만 포함한다. 기존 작성일에서 발행일/입금일을 추측하여 채우지 않는다.
- 기존 견적서 재분석·AI 금액 수정은 날짜 필드를 보내지 않는 한 날짜를 유지한다.
- 날짜 입력·수정은 활성 관리자 `dbqls110@gmail.com` 본인 계정만 허용한다. 프로젝트는 projects 편집 권한, 직접 장부는 companyFinance 편집 권한도 필요하다. 다른 관리자·직원·DOT·외부 계정은 불가.
- 전용 날짜 버튼뿐 아니라 프로젝트 금액 추가·수정과 직접 회사 매출 등록도 같은 서버 계정 검사를 적용한다. 다른 계정의 일반 금액 수정은 날짜 필드를 보내지 않아 기존 날짜가 유지된다.

운영 반영에는 migration 적용 후 앱 배포가 필요하다. 이 문서는 세무상 매출 인식 규정이 아니라 사용자가 지정한 ERP 관리 집계 정책을 정의한다.
