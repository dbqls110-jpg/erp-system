# ERP → 공간 DB 요청 · 2026-09-09

ERP 쪽에서 자료를 쓰다 막힌 지점 셋입니다. 급한 순서대로 적었습니다.
현재 ERP 가 들고 있는 공간은 **4,288곳**입니다(9/9 정본 기준, 삭제·병합 반영 완료).

---

## 1. 요금을 모르는 1,365곳 (32%)

```
요금(대관료_4시간환산) 없음     1,365곳
  그중 예약URL 있음            1,266곳
  그중 전화번호 있음            1,358곳
```

**예약 URL 이 있는 1,266곳은 홈페이지에 요금표가 걸려 있을 가능성이 높습니다.**
사람이 하나씩 열어보는 대신 그쪽에서 긁어 주시면 좋겠습니다.

우선순위를 둔다면 **정원 300~999명 구간의 276곳**이 먼저입니다.
문의가 가장 많이 들어오는 규모이고, 중개 수수료도 이 구간이 큽니다.
그 다음이 1,000명 이상 80곳입니다.

요금을 넣으실 때 `요금_신뢰도` 와 `요금_출처` 를 함께 채워 주십시오.
ERP 는 그 두 칸으로 추천 순위를 매깁니다. 금액만 있으면 "못 믿는 값" 으로 처리합니다.

## 2. 주말·영리 대관 가부가 절반 비어 있습니다

```
토요일   빈칸 2,170곳 (51%)
일요일   빈칸 2,185곳 (51%)
공휴일   빈칸 2,193곳 (51%)
영리대관 빈칸 2,022곳 (47%)
```

**이게 요금보다 더 급합니다.**

우리 고객은 기업이고 행사는 주말에 합니다. 이 칸이 비면 ERP 는 그 공간을
"모른다" 는 경고만 달고 추천에 올립니다. 그러면 담당자가 전화를 걸고 나서야
*"저희는 주말 대관 안 합니다"* · *"영리 목적은 안 받습니다"* 를 듣습니다.

**틀린 추천이 아니라 헛걸음을 만드는 칸**이라 우선순위가 높습니다.

역시 **300~999명 구간부터** 부탁드립니다. 주말 빈칸 526곳, 영리 빈칸 498곳입니다.

값은 지금 쓰시는 어휘 그대로 주시면 됩니다(가능 · 불가 · 조건부 · 승인필요 · 미상).
ERP 가 이미 그 값들을 읽습니다.

## 참고 · 지난 인계 건 처리 결과

```
삭제 대상 1,409곳   →  DB 에 실재한 1,021곳 삭제
병합 대상    80쌍   →  35쌍 삭제(남길 쪽만 있던 45쌍은 이미 처리돼 있었음)
자치구 표기        →  '서울 강남구' 형식으로 통일. 그쪽 형식에 맞췄습니다
요금 신뢰도 매핑    →  확인=확정 · 미검증/낮음=못 믿음 으로 반영
요금 출처 가중치    →  공시가 0.5 → 0.2 (실측 정확도 근거 반영), AG발굴 0.7 유지
```

**부탁 하나.** 행 열쇠를 `이름 + 위치` 로 바꿨습니다.
전에는 자치구도 넣었는데, 자치구 표기가 바뀌자 4,150행이 통째로 다른 행으로 읽혀
갱신 대신 복제가 될 뻔했습니다(5,345 → 9,493). **이름과 위치는 되도록 그대로 두시고,
바꾸실 일이 있으면 미리 알려 주십시오.**
