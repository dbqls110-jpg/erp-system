# 개인 메일 자동 수신

## 범위와 주기

- 현재 요청자의 ERP 계정 `dbqls110@gmail.com`이 소유한 연결만 대상으로 한다. 박석영 팀장 등 다른 계정으로 확대하지 않는다.
- Gmail은 정확히 `ERP문의` 라벨, 네이버는 현재 `INBOX`만 수신한다. Gmail 라벨이 없으면 오류로 표시하며 받은편지함 전체로 폴백하지 않는다.
- GitHub Actions `private-inbox-sync.yml`이 약 5분마다 인증된 POST `/api/agent/inbox/sync`를 호출한다. 회사 PC·브라우저와 무관하다. GitHub의 예약 실행은 지연/누락될 수 있으므로 실시간 보장으로 안내하지 않는다.
- 기존 범위인 최근 30일·한 번에 최대 40건의 제공자 읽기를 유지한다. 원본 읽음·이동·삭제·발송은 하지 않는다. 자동 작업은 기존 ERP 사본·연락 일정도 삭제하지 않는다.
- 이미 저장한 제공자 메시지 ID는 본문을 다시 다운로드하지 않는다. Gmail 라벨을 나중에 붙인 메일도 놓치지 않도록 목록 확인은 계속하되 본문은 새 메일만 받는다.
- UI ‘수신’ 버튼은 즉시 확인이 필요할 때 계속 사용할 수 있다. 화면은 기존 useVisiblePolling으로 저장된 사본을 갱신하며 새 제공자 조회를 브라우저에서 반복하지 않는다.

## 인증·동시성

- 기존 ERP_MAINTENANCE_SECRET만 사용한다. 키 일치·길이·별도 키와 충돌 여부를 검증하기 전에는 DB를 조회하지 않는다. 요청 본문의 ownerId/mailboxId는 받지 않는다.
- 소유자의 최신 활성·내부 계정 여부와 문의 권한을 검사한다. 조회 중 비활성화·재연결·연결 해제·리스 만료가 발생하면 결과를 저장하지 않는다.
- 자동·수동 모두 기존 메일함 DB 리스와 고유 (mailboxId, providerMessageId)를 공유한다. 5분 예약의 제공자 처리 시간·실행 지연을 흡수하도록 자동 수신 성공/일시 오류의 중복 방지 쿨다운은 4분이며, 인증·라벨 설정 오류는 1시간 뒤 재확인한다. 사용자 수동 재시도는 기존 60초 제한을 유지한다.
- 한 실행 최대 4연결, 동시에 2연결로 제한한다. 한 연결의 실패가 다른 연결을 중단하지 않는다. 실패 응답과 Actions 로그에는 본문·메일 주소·토큰 없이 HTTP 상태/집계 숫자만 표시한다.
- 새 DB 마이그레이션이나 OAuth 권한 확대는 없다. 다른 직원 자동 수신은 별도의 승인·설정 범위를 정해야 한다.

## 활성화·검증

1. 검증 후 승인된 변경만 main에 동기화하여 Render 배포를 완료한다.
2. GitHub Actions 기존 Secret ERP_MAINTENANCE_SECRET과 ERP_MAINTENANCE_ENABLED=true를 확인한다. 값은 출력하거나 새 키로 덮어쓰지 않는다.
3. 저장소 Actions Variable PRIVATE_INBOX_SYNC_ENABLED=true를 설정한다. false로 변경하면 이 작업만 중지하며 DOT·문의 발송 작업은 그대로 유지한다.
4. workflow_dispatch 1회 및 예약 실행 1회의 상태/집계와 운영 ‘최근 수신’ 갱신을 확인한다. 전달 검증용으로 임의 고객 메일을 생성·발송·라벨 지정하지 않는다. 빈 Gmail 라벨은 0건 수신이 정상이다.
5. 수신 실패가 있으면 제공자 오류 코드는 메일 연결 카드에 보존하고, 인증 만료인 경우 본인 재연결을 안내한다.

배포·예약 활성화 전에는 자동 수신이 운영 중이라고 안내하지 않는다.

## GitHub 예약 지연 시 Cloudflare 대체 경로

GitHub에 `schedule` 실행 기록 자체가 없으면 ERP나 메일 제공자 실행 실패와 구분한다. 2026-11-20에는 수동 클라우드 작업은 두 메일함에 성공했으나 40분 넘게 예약 이벤트가 없었다. 같은 저장소의 다른 분 단위 예약에도 시간 단위 공백이 있었다.

1. Render에 32바이트 난수의 소문자 64자리 hex를 `ERP_PRIVATE_INBOX_CRON_SECRET`으로 설정한다. 기존 통합 키를 재사용하지 않는다. 새 전용 키는 메일 수신 POST만 호출할 수 있으며 Git·채팅·로그에 넣지 않는다.
2. 동일한 전용 키를 `erp-private-inbox-cron` Worker의 Secret에 입력한다. `ops/private-inbox-cron/wrangler.toml`을 기준으로 배포한다. Worker에 공개 HTTP URL이나 미리보기 URL을 열지 않는다.
3. `*/5 * * * *` 첫 **scheduled** 이벤트의 성공 로그와 ERP에서 두 메일의 수신 시각 갱신을 대조한다. 로그의 `synced=2`는 메일 2건이 아니라 두 메일함의 수신 확인 성공이다. 새 메일이 없더라도 확인은 성공할 수 있다.
4. 확인 후 GitHub의 자동 스케줄을 끈다. 수동 복구 및 다른 GitHub 워크플로에는 기존 인증을 유지한다. 전환 중 중복 요청이 와도 DB 리스로 충돌을 방지한다.

Cloudflare에는 메일 계정 정보나 메일 본문을 보내지 않는다. Worker는 고정된 ERP 주소를 호출하며 검증된 집계와 시각만 로그에 남긴다. 중지 시 Worker 트리거를 끄고 Render의 전용 키를 제거한다.
