# 프로젝트 연락 상태

로컬 구현: 2026-11-18. 운영 DB 마이그레이션·push·배포는 승인 전까지 미실행.

## 한 원본

- 문의 통합 목록에 프로젝트를 추가한다. 프로젝트 상세와 문의 통합의 연락 상태·메모·다음 연락은 같은 `project_contact_states`를 읽고 쓴다.
- 상태: 미기록 / 견적서 보냄 / 전화함 / 회신 대기 / 진행 확정 / 보류 / 연락 종료.
- 프로젝트의 진행 중·완료·보류, 진행률, 견적서 원본, 매출·매입은 별도이며 연락 상태 저장으로 바꾸지 않는다. 견적서 업로드는 실제 발송의 증거가 아니므로 자동으로 ‘보냄’ 처리하지 않는다.
- 다음 연락 일시는 한국시간으로 명시 입력한다. 비워두면 미정이며 생성일·마감일·오늘로 채우지 않는다. 이 기능은 자동 연락·메일 발송·전화·일정 알림을 실행하지 않는다.
- `project_contact_logs`는 변경 이력을 보관한다. 화면은 최근 10개를 보여주지만 이전 기록을 삭제하지 않는다. 기록 시각은 저장 시각이지 실제 통화·발송 시각의 증명이 아니다.
- 프로젝트 목록 조회는 최근 수정순 최대 200개이다. 연락을 기록하면 프로젝트의 시스템 수정 시각만 갱신한다. 재무 발생일·계산서 발행일·입금 예정일은 변경하지 않는다.

## 권한

사용자 승인: 2026-11-18 ‘내부 직원이 함께 조회·수정’.

- 프로젝트 메뉴 읽기 권한이 있는 활성 내부 직원이 연락 상태를 조회한다. 쓰기는 프로젝트 메뉴 수정 권한도 필요하다.
- 세션과 현재 DB 사용자 레코드를 모두 확인한다. 관리자로 로그인한 오래된 세션이 있어도 DB에서 외부·비활성·에이전트로 전환되면 새 연락 API는 거부한다.
- partner/customer/venue 연결 계정, 외부 역할, 승인 대기, DOT, 에이전트는 차단한다. 외부 프로젝트 허용 목록 DTO에 연락 상태·메모를 추가하지 않는다.
- 문의 탭·홈페이지 문의의 기존 두 계정 제한은 그대로다. 다른 내부 직원은 프로젝트 상세에서 연락 기록을 사용한다.
- 개인 Gmail·네이버 원문·연결 자격 증명·개인 연락 일정은 공유하지 않는다.
- 추가 테이블은 RLS 활성화, 공개 클라이언트 정책 없이 서버 역할로만 접근한다.

## 동시성·복구

- 프로젝트 행 잠금과 연락 상태 버전 비교를 함께 사용한다. 같은 버전의 서로 다른 수정은 하나만 성공한다.
- 사용자 저장 요청 ID를 이력 PK로 써 재전송을 멱등 처리한다. 동일 ID로 다른 내용을 제출하면 거부한다.
- 상태 갱신·변경 이력 저장·시스템 수정 시각 갱신은 같은 트랜잭션이다.
- 충돌 시 입력을 유지하며 새 기록을 불러온 뒤 다시 저장할 수 있다. 오류 응답은 알려진 입력 오류만 공개하고 DB/토큰/스택은 반환하지 않는다.

## 검증 경계

- 단위 테스트와 격리 PostgreSQL에서 저장·버전 충돌·8회 재전송·일반 직원 공유·권한 회수·외부/DOT 차단을 검증한다.
- 격리 화면은 실제 컴포넌트와 실제 로컬 DB를 쓰되 세션·메일 공급자만 검증용 어댑터로 대체한다. 고객에게 연락하지 않는다.
- 운영 배포·실제 OAuth 세션·운영 사용자 권한 재검증은 별도 승인 이후 수행한다.

- 채널 선택 → 해당 선 → ERP 원 → 통합함의 짧은 1회 SVG/CSS 모션. 새 런타임 패키지를 추가하지 않는다.
- 실제 전송·수신 성공이나 AI 처리 상태를 뜻하지 않는다. 미연결 채널은 선택·모션 모두 막는다.
- 선의 시작·끝을 채널과 통합함 경계에 맞추며 채널 개수에 맞춰 높이를 계산한다.
- 모션 감소 설정·모바일·숨겨진 탭에서는 공간 이동을 생성하지 않는다. 무한 루프나 새 폴러가 없다.
