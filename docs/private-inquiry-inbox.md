# 개인 메일 통합 문의함

상태(2026-11-18): 기본 통합함은 운영 중이다. 11월 17일 본인 Gmail 연결 저장 및 네이버 실제 수신 40건을 확인했다. Gmail 수신은 아직 오류가 있어 별도 재확인이 필요하다. 가독성·메일 확인 처리·채널 모션·프로젝트 연락 상태 변경은 로컬 구현이며 운영 배포 승인 대기다.

## 접근 범위

- 기존 문의 탭 승인 계정(본인·박석영 팀장) 제한 유지. 다른 직원·외부 계정으로 공개 범위를 넓히지 않는다.
- 홈페이지 문의·공간등록·대관 원본은 기존 두 담당자가 공유한다.
- 메일 연결·메일 사본·다음 연락 일정은 연결한 ERP 사용자 본인만 조회한다. 관리자 역할도 타인의 메일을 조회할 API가 없다.
- 프로젝트 연락 상태·메모는 사용자 승인(2026-11-18)에 따라 프로젝트 권한이 있는 내부 직원이 공유한다. 문의 탭 자체의 두 계정 제한이나 개인 메일 공유 범위를 넓히는 것은 아니다. 상세 규칙은 `project-contact-tracking.md` 참고.
- 비밀값은 AES-GCM 암호문으로만 서버 DB에 저장한다. 클라이언트 조회 DTO·로그에는 토큰/앱 비밀번호를 반환하지 않는다.
- 신규4테이블 RLS 활성화, 공개 API 정책 없음. 서버의 기존 DB 역할만 이용한다.

## 사용 순서

1. 기본 기능은 `20261113090000_private_inbox` migration을 사용한다. 이미 운영 중인 환경에는 적용 이력부터 확인하며 수동 재생성하지 않는다.
2. 문의 → 통합 보기 → 내 메일 연결.
3. Gmail: 먼저 Gmail에 `ERP문의` 라벨을 만들고 필요한 메일에 지정. 라벨명을 입력하고 Google 연결 버튼에서 계정 선택·읽기 권한 동의. 한 사용자가 여러 계정을 연결할 수 있다.
4. Google OAuth 프로젝트에서 Gmail API가 활성화되어야 한다. 기존 Google 클라이언트의 등록된 `/api/admin/drive-callback` URI를 분기해서 쓰며 Drive/알림 발송 토큰을 덮어쓰지 않는다. 새 Gmail 읽기 scope는 제한 scope이므로 Google 앱 게시 상태/테스트 사용자/검증 정책을 확인한다. 권한 자체는 전체 메일 읽기지만 애플리케이션 수집은 지정 라벨만이다.
5. 네이버: PC 메일 설정에서 IMAP 사용, 네이버ID 2단계 인증 후 앱 비밀번호 생성. 일반 비밀번호가 아닌 앱 비밀번호를 ERP 입력란에 직접 입력. 사용자 지정 메일함 또는 `INBOX` 선택.
6. 연결된 계정의 **수신** 버튼으로 가져오기. 자동으로 메일을 발송하거나 원본 읽음 상태를 바꾸지 않는다. 현재 버전은 백그라운드 메일 수집 예약이 아니라 명시적인 수신 버튼 방식이다. 화면의 저장 사본/연락 일정은 보이는 탭에서만60초 갱신한다.
7. 원문 선택 → 내 다음 연락 일정에 KST 일시와 메모 입력 → 저장. 일시 미정이면 비워 둔다. 알림·자동 발송은 제공하지 않는다.

## 수집/저장 제한

- 최근30일, 지정 라벨/메일함의 최근40건/수신. 화면은 최신200건. 계정 최대10개.
- Gmail 본문은 text/plain만 표시. HTML·추적 이미지·첨부파일은 브라우저에 표시하거나 자동 다운로드하지 않는다.
- 네이버는 TLS 고정 서버 `imap.naver.com:993`, readOnly 메일함. 원문2MB를 넘는 메일은 건너뛰며 텍스트 본문만 최대20,000자 저장. 원본 메일 보존.
- 외부 동기화 타임아웃, 계정별DB리스와60초 쿨다운, provider message ID 고유 제약으로 중복 저장 방지.
- 폴더를 바꾸면 이전 범위 사본과 해당 일정 제거. 연결 해제 시 ERP 사본·일정을 제거하고 원본 메일은 유지. Google 권한 자체 철회는 Google 계정의 연결된 앱에서 가능.
- 웹사이트 일정 키는 행번호가 아닌 기존 접수 identity 해시. 일정 수정은 version 비교로 오래된 화면의 덮어쓰기를 차단한다.

## 확인 범위와 남은 작업

- 서비스 단위 검증: 인증 실패 시 DB 접근 없음, 조회 본인 필터, 타인 메일 일정/연결 해제 차단, 버전 충돌, 중복 동기화 리스, 폴더 변경 정리, KST 파싱.
- 사용자 직접 Google 동의와 네이버 앱 비밀번호 입력 후 연결 저장을 확인했다. 2026-11-17 17:16 KST에 네이버 수신 재실행 후 동기화 시각 갱신 및 40건 표시를 확인했다. 원본 메일 삭제/이동/발송은 하지 않았다.
- Gmail은 연결 저장과 실제 수신 성공을 구분한다. 현재 수신 실패의 정확한 상위 서비스 오류는 미확정이다. 로컬 수정은 알려진 라벨 없음/API 비활성/권한/재승인/IMAP 인증/시간초과 오류를 안전한 안내로 구분하고 원문 오류나 토큰을 표시하지 않는다. 배포 후 해당 계정으로 수신 재확인이 필요하다.
- 가상 자료 UI 검증은 운영 DB·메일 서버를 호출하지 않는다. 캡처는 연결 완료나 실수신 성공 증거가 아니다.

공식 안내: [Gmail scope](https://developers.google.com/workspace/gmail/api/auth/scopes), [Naver 외부 메일 인증](https://help.naver.com/service/30029/contents/24347).

## 2026-11-18 가독성·확인 처리·모션 수정

- 메일 설정 기본 접힘, 계정 추가 폼도 별도 접힘으로 분리. 연결 완료 상시 배너 제거, 서비스 변경 시 이전 오류 문구 제거.
- 기본 본문 14px, 날짜·상태 13px, 제목 16px로 ERP 타이포를 따른다. 우측 상세는 340px이며 좁은 화면은 목록 아래로 배치한다.
- 사용자가 선택한 기존 연결 그림·목록 구성을 유지한다. 선이 실제 채널과 통합함 경계에 닿도록 좌표계를 통일했다. 모바일에서는 읽을 수 있는 채널 버튼 격자로 바꾸고 큰 연결 그림은 숨긴다.
- 중간 폭과 모바일은 간편 목록, 넓은 화면은 표를 유지한다. 모바일에서 항목 선택 시 본문에 초점/스크롤 이동, 목록 복귀 버튼 제공.
- 텍스트 메일에 남은 HTML 주석/조건부 레이아웃은 표시 복사본에서만 제거한다. 저장 원문은 변경하지 않으며 HTML을 실행하거나 추적 이미지를 불러오지 않는다.
- 알려진 상대 이름은 기본적으로 전부 표시하며 개인정보 가림은 선택 스위치로 유지한다. 본인 메일/일정 권한, 홈페이지 공유 범위, 기존 개별 보드는 유지한다.
- 메일 `readAt`을 ERP에만 추가한다. 최초 자동 선택은 읽음 처리하지 않고 명시적인 메일 선택 또는 선택한 여러 메일 확인 처리 때 저장한다. 답변은 필요 없으며 원본 Gmail/네이버의 읽음·삭제·이동 상태는 변경하지 않는다.
- 이미 확인한 상태를 늦게 도착한 조회 응답으로 되돌리지 않는다. 빠르게 여러 메일을 선택하면 대기 집합으로 묶어 누락 없이 순차 확인한다. 확인 시각은 최초 값만 보존한다.
- 채널 숫자는 현재 조회한 목록의 건수, 미확인 숫자는 그 메일 목록 중 ERP 미확인 건수다. 메일은 최대 최신 200건, 프로젝트는 최대 최근 수정 200개라는 조회 한계를 숨기지 않는다. 공급자 메일함 전체 건수를 뜻하지 않는다.
- 채널 선택 시 점이 ERP 원을 거쳐 통합함으로 이동하는 1회 모션을 제공한다. 미연결·모바일·숨겨진 탭·모션 감소 설정에서는 실행하지 않는다. 실제 전송 성공이나 AI 처리를 뜻하지 않는다.
